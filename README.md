# your-call

> It's your call. AI가 선택지를 펼쳐 놓아도, 판단하고 책임지는 것은 사람이다.

결정을 대화 밖에 사실대로 남기고, 의도는 사람의 말로만 채우게 하는 Claude Code 플러그인입니다.

AI와 일하면 결정이 각자의 대화 안에서 일어나고, 다른 사람은 결과물만 봅니다. your-call은 그 대화에서 일어난 일(입력, 밝힌 의도, 선택지와 고른 것과 버린 것, 중단, 불러온 스킬, 위임, 바꾼 파일)을 hook이 사실 그대로 기록하게 합니다. AI는 그 기록을 쓸 수 없고, 의도나 이유를 짐작해 채우지 못합니다.

**상태**: 0.2.0 · 1단계(기록)와 2단계(스펙: 통과 기준은 사람이, 테스트는 AI가) 완료. 3단계(리뷰: 과정까지 리뷰)를 만들고 있습니다. 아래 「리뷰어에게 기록 보여 주기」는 아직 공개되지 않은 main에만 있습니다.

## 설치

```
/plugin marketplace add sangwookp9591/your-call
/plugin install your-call@your-call
```

Node가 필요합니다. Claude Code 2.1.311, Node 22에서 확인했습니다.

## 쓰는 법

**의도는 사람이 먼저 밝힙니다.** 뒤에 남을 결정이라면 입력을 `why:`로 시작하세요. 빈 줄 전까지가 의도로 기록되고, 빈 줄 뒤에 지시를 이어 씁니다.

```
why: 만료 판정을 서버 시간 기준으로 통일
타임존 버그가 반복돼서

쿠폰 만료 로직 고쳐줘
```

| 명령 | 하는 일 |
|---|---|
| `/your-call:declare` | 이번 세션에 밝힌 의도를 보여 줍니다. 없으면 "무엇을, 왜"만 묻습니다. AI는 의도를 대신 쓰거나 예시를 만들지 않습니다. |
| `/your-call:ledger` | 이번 세션 기록을 입력 단위로 묶어 보여 줍니다. 사람이 개입한(⚑) 턴과 그 비율, 의도, 선택, 중단, 바꾼 파일. 사실이 먼저, 🤖 AI의 마지막 말은 맨 끝에 짧게. |
| `/your-call:ledger all` | 프로젝트의 모든 세션을 합친 요약과 최근 세션 10개. |

두 명령 모두 사람만 부를 수 있고, 기록을 읽기만 합니다.

## 스펙에서 시작하기

**통과 기준(케이스)은 사람이 확정하고, 테스트는 AI가 씁니다.** 순서보다 중요한 것은 소유권입니다. 사람이 보는 것은 테스트 코드가 아니라 케이스 목록에 빠진 것이 없는지입니다.

```
/your-call:spec coupon-expiry       ① AI가 케이스 초안과 빠진 것을 근거와 함께 제안
        ↓ 사람이 고름              ② 고른 것만 hook이 cases.md에 옮김
"cases.md의 케이스로 테스트를 써 줘"  ③ 테스트 이름은 `C1: 문장` 그대로
/your-call:coverage coupon-expiry   ④ 케이스와 테스트의 짝을 별도 컨텍스트에서 확인
/your-call:testdoc test/coupon.test.js  ⑤ 테스트가 문서로 읽히는지 별도 컨텍스트에서 확인
```

| 명령 | 하는 일 |
|---|---|
| `/your-call:spec <작업>` | 무엇을, 왜 하는지 먼저 묻습니다. 그다음 저장소를 읽고 `proposals.md`에 제안(케이스 초안, 빠진 케이스, 모호한 조건, 숨은 전제, 기존 동작과 어긋남)과 근거를 날짜별로 덧붙인 뒤, 확정할 케이스를 고르게 합니다. 추천 표시는 붙이지 않습니다. |
| `/your-call:coverage <작업> [테스트 파일...]` | `case-coverage` 에이전트가 케이스마다 짝 있음, 짝 없음, 단언이 다름, 문장이 다름을 파일:줄 근거와 함께 돌려줍니다. 새 케이스를 제안하거나 테스트를 고치지 않습니다. |
| `/your-call:testdoc <테스트 파일...>` | `test-as-doc` 에이전트가 이름(조건과 기대), 준비(도메인 어휘), 단언(설명 없는 숫자, 0과 1은 예외)을 인용과 함께 돌려줍니다. 테스트를 고치지 않습니다. |

세 명령 모두 사람만 부를 수 있습니다. 두 에이전트는 읽기 도구(`Read`, `Grep`, `Glob`)만 갖고, 테스트를 쓴 대화의 짐작 없이 작업 이름과 경로만 받습니다. "문제없음" 같은 판정만 돌려주는 것은 형식 위반입니다.

**스펙 파일은 커밋됩니다.** 팀과 함께 보는 기준이기 때문입니다.

| 파일 | 누가 쓰나 | 내용 |
|---|---|---|
| `.your-call/spec/<작업>/cases.md` | 사람이 확정한 것을 hook이 옮김 | `- C1: 문장` 한 줄에 케이스 하나. 번호는 늘어나기만 합니다 |
| `.your-call/spec/<작업>/proposals.md` | AI (`/your-call:spec`) | `## <날짜> 검토` 섹션마다 제안과 찾아본 것, 근거 |

- **확정은 사람의 선택으로만 들어갑니다.** `case-capture`는 header가 `케이스 확정`이고 질문이 `[<작업>]`로 시작하는 질문의 답만 봅니다. 고른 문장, 직접 쓴 답(한 줄에 하나)을 `cases.md`에 옮기고, 같은 문장이 이미 있으면 기존 번호를 알려 줍니다.
- **AI는 `cases.md`를 쓸 수 없습니다.** `spec-guard`가 `Write`, `Edit`, `NotebookEdit`로 `.your-call/spec/*/cases.md`를 쓰려는 호출을 막고, `proposals.md`에 근거와 함께 적으라고 돌려보냅니다. 사람은 에디터로 직접 고칠 수 있습니다.
- **케이스를 지울 때는 줄을 지우지 말고 문장에 취소선(`- C2: ~~문장~~`)을 그으세요.** 번호가 남아 다시 쓰이지 않습니다.

## 리뷰어에게 기록 보여 주기

기록(`ledger/`)은 입력 원문이 들어 있어 커밋되지 않습니다. 리뷰어가 과정을 보려면 **사람이 고른 만큼만** 커밋되는 공유본으로 옮깁니다.

```
/your-call:share                 이번 세션의 턴을 /your-call:ledger와 같은 번호로 나열 (파일은 쓰지 않음)
/your-call:share 1 4             1번, 4번 턴의 입력 원문을 넣어 .your-call/shared/<세션>.md 작성
/your-call:share <session_id> 2  지난 세션도 같은 방식
```

- **기본으로 들어가는 것**: 턴마다 의도, 선택(제시된 것, AI 추천, 고른 것, 버린 것, 직접 쓴 답, 비어 있는 이유), 중단, 스킬, 위임 종류와 설명, 바꾼 파일, 막힌 쓰기. 맨 위에 기간과 ⚑ 개입 턴 수.
- **사람이 고른 턴에만 들어가는 것**: 입력 원문. 나머지 턴은 "원문 공유 안 함"으로 남습니다.
- **들어가지 않는 것**: AI의 마지막 말과 위임 원문. 리뷰어는 AI의 설명보다 사실을 먼저 봅니다.
- **쓰지 않는 경우**: 없는 번호나 기계가 넣은 턴의 번호를 주었을 때, 그리고 공유본에 `sk-…`, `ghp_…`, `AKIA…`, 48자 이상의 hex 같은 토큰처럼 보이는 문자열이 섞일 때. 어느 턴인지 알려 주고, 토큰 자체는 다시 보여 주지 않습니다.
- 같은 기록과 같은 번호면 바이트가 같은 파일이 나옵니다. 공유본의 diff를 리뷰할 수 있습니다.

**공유본은 스크립트만 씁니다.** `/your-call:share`는 사람만 부를 수 있고, AI는 공유할 번호를 추천하지 않습니다.

- `share-guard`: AI가 `Write`, `Edit`, `NotebookEdit`로 `.your-call/shared/` 아래를 쓰려는 호출을 막습니다. 고칠 것이 있으면 사람이 에디터로 고칩니다.
- `share-run-guard`: AI가 Bash로 공유본 스크립트를 직접 실행해 공개할 턴을 대신 고르려는 호출을 막습니다. 사람의 `/your-call:share`는 그대로 동작합니다.

## 무엇을 기록하나

`.your-call/ledger/<session_id>.jsonl`에 이벤트 하나가 한 줄로 쌓입니다. 모든 줄에는 같은 입력을 묶는 `prompt_id`가 있습니다.

| 줄 | 언제 | 남기는 것 |
|---|---|---|
| `session-open` | 세션이 시작될 때 | 시작 이유 (startup, resume, …) |
| `prompt` | 입력이 들어올 때 | 입력 원문 그대로 |
| `intent` | `why:`로 시작하는 사람의 입력 | 밝힌 의도 (사람의 말 그대로) |
| `interrupt` ⚑ | 사람이 Esc로 멈춘 뒤 다음 입력 때 | 응답 중 또는 도구 사용 중 |
| `choice` ⚑ | AI의 질문에 답했을 때 | 제시된 것, AI의 추천, 고른 것, 버린 것, 직접 쓴 답. 이유는 항상 비워 둡니다 |
| `skill` | 스킬을 불러왔을 때 | 이름, 사람이 불렀는지 AI가 불렀는지 |
| `agent` | AI가 에이전트에게 위임했을 때 | 종류, 설명, 위임 원문 |
| `edit` | `Write`, `Edit`, `NotebookEdit`로 파일을 바꿨을 때 | 경로만 (내용은 남기지 않습니다) |
| `turn-close` | 응답이 끝났을 때 | AI의 마지막 말 원문 |
| `blocked` | AI가 기록을 쓰려다 막혔을 때 | 도구와 경로 |

**기록은 기본적으로 커밋되지 않습니다.** 입력 원문이 그대로 들어가므로, 처음 기록할 때 `.your-call/.gitignore`에 `ledger/`를 넣습니다. 이미 있는 `.gitignore`는 건드리지 않습니다. 리뷰어에게 보여 줄 것은 `/your-call:share`로 골라 옮깁니다.

**AI는 기록을 쓸 수 없습니다.** `ledger-guard`가 `Write`, `Edit`, `NotebookEdit`로 `.your-call/ledger/` 아래를 쓰려는 호출을 막습니다. 상대 경로, `..`, 심볼릭 링크, `/var`와 `/private/var` 같은 실제 경로 차이, 대소문자 차이로 돌아 들어와도 막습니다. 사람은 에디터로 직접 고칠 수 있습니다.

## 알려진 빈틈

- **기계가 넣은 입력을 거르지 못할 수 있습니다.** `intent-capture`는 사람이 넣은 입력만 의도로 인정하려고 hook 입력의 `source`를 봅니다. 그런데 Claude Code 2.1.311에서는 `-p` 실행과 대화형 입력창 모두 이 값이 비어 있었고, 값이 없으면 사람의 입력으로 봅니다. 그래서 작업 알림 같은 기계가 넣은 턴이 `why:`로 시작하면 의도로 기록될 수 있습니다. Claude Code가 `source`를 보내면 그대로 걸러집니다.
  - 실제 사례: 백그라운드 에이전트가 결과를 돌려줄 때 Claude Code가 넣는 `<agent-message …>` 턴이 `source: null`인 `prompt` 줄로 기록됩니다. 기록은 들어온 사실 그대로 두고, `/your-call:ledger`가 셀 때만 이 형식을 사람 입력에서 빼고 뺀 수를 보여 줍니다.
- **`Bash`로 바꾼 파일은 `edit` 줄에 남지 않습니다.** 이때 AI의 마지막 말에는 바꿨다는 말이 있어도 `edit` 줄은 없을 수 있습니다.
- **`ledger-guard`는 `Write`, `Edit`, `NotebookEdit`만 봅니다.** `Bash`로 기록 파일에 직접 쓰는 우회는 막지 못합니다.
- **세션의 마지막 중단은 남지 않을 수 있습니다.** 중단은 다음 입력 때 transcript에서 찾기 때문에, 중단한 뒤 입력 없이 세션을 끝내면 기록되지 않습니다. transcript 형식은 Claude Code의 공식 계약이 아니라서, 형식이 바뀌면 중단이 기록되지 않을 수 있습니다.
- **두 명령은 문서에 없는 환경 변수 `CLAUDE_CODE_SESSION_ID`로 이번 세션을 찾습니다.** 이 값이 없으면 추측하지 않고 "세션을 알 수 없습니다"라고 말합니다.
- **`spec-guard`도 `Write`, `Edit`, `NotebookEdit`만 봅니다.** `Bash`로 `cases.md`에 직접 쓰는 우회는 막지 못합니다.
- **`share-run-guard`는 명령 문자열만 봅니다.** `node`, `share.js`, 플러그인 표식(`your-call` 또는 `CLAUDE_PLUGIN_ROOT`)이 함께 있을 때만 막으므로, 변수 조합이나 파일 복사 뒤 실행처럼 작정한 우회는 막지 못합니다.
- **토큰 검사는 정해 둔 형식만 봅니다.** 형식이 없는 비밀(비밀번호, 고객 데이터)은 걸러지지 않습니다. 원문을 고르기 전에, 그리고 커밋 전에 사람이 공유본을 직접 열어 보세요.
- **마지막 케이스 줄을 통째로 지우면 그 번호가 다시 쓰입니다.** 번호는 파일에 남은 가장 큰 번호(취소선 포함) 다음으로 매기기 때문입니다. 취소선을 그으면 생기지 않습니다.

## 바뀐 것

- **다음 버전(작업 중)**: 3단계(리뷰). `/your-call:share`, hook `share-guard`, `share-run-guard`.
- **0.2.0**: 2단계(스펙). `/your-call:spec`, `/your-call:coverage`, `/your-call:testdoc`, hook `case-capture`, `spec-guard`, 에이전트 `case-coverage`, `test-as-doc`.
  - 고침: 여러 개를 고르는 질문에서 직접 쓴 답이 `"…"`처럼 따옴표에 감싸인 채 `choice` 줄의 `other_text`에 기록되던 것을 풀어서 기록합니다. Claude Code가 이 답을 JSON 문자열로 감싸 보내기 때문이었습니다. 0.1.0으로 남은 기록은 그대로입니다.
- **0.1.0**: 1단계(기록).

## 개발

```
npm install
npm run typecheck   # JS + JSDoc을 TypeScript 7이 strict로 검사
npm test            # 케이스마다 짝지은 테스트, 순서대로 실행
npm run test:e2e    # 실제 Claude Code 세션을 엶 (모델 호출 비용이 듦)
```

플러그인 코드는 빌드 없이 그대로 실행됩니다. 리뷰한 코드가 곧 실행되는 코드입니다.
